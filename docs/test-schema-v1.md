# Test schema version 1

YAML uses `schemaVersion: 1`, a non-empty `name`, optional `redactValues` (literal sensitive strings), and 1–20 `tests`. Every object is strict: unknown keys and YAML custom tags, aliases and duplicate keys are rejected. UTF-8 suite/workflow/fixture files are bounded at 1 MiB; fixtures are JSON objects bounded at 64 KiB. Paths resolve relative to the suite and must remain under the real current project directory, including after symlink resolution. No JavaScript, shell, plugins or executable hooks in test configuration.

```yaml
schemaVersion: 1
name: contact
redactValues: []
tests:
  - id: correct
    workflow: ../workflows/correct.json
    fixture: ../fixtures/contact.json
    timeoutMs: 30000
    mocks:
      - id: crm
        method: POST
        path: /contacts
        headers: {}                 # lowercase selected header names
        bodyFields: {}              # RFC 6901 pointer -> exact JSON value
        responses:
          - kind: json
            status: 201
            json: {id: fake-contact-1}
            delayMs: 0
    assertions:
      - target: execution.status
        equals: success
      - target: requests.count
        mockId: crm
        equals: 1
      - target: request.json
        mockId: crm
        requestIndex: 0
        pointer: /email
        equals: customer@example.test
      - target: node.json
        nodeId: map
        runIndex: 0
        outputIndex: 0
        itemIndex: 0
        pointer: /email
        equals: customer@example.test
```

Test IDs/mock IDs are ASCII letters/digits/underscore/hyphen, 1–64 characters, unique within their scope. Each test requires `workflow`, `fixture`, `mocks` (may be empty), and 1–100 assertions including an explicit terminal `execution.status`. Timeout is 1,000–120,000ms, default 30,000ms. No skip flag. Assertions must reference existing mocks/node IDs. There is no assertion-failure-to-pass switch: deliberately broken suites return 1.

Each mock has one method/path pair, unique within the test; methods: GET/POST/PUT/PATCH/DELETE/HEAD. Paths use literal `/[A-Za-z0-9/_-]*` only; no query strings, wildcards, origins or forwarding. Up to 20 mocks and 20 responses per mock. All selected request fields must match using exact deep equality. An unmatched request is captured and receives 409. An exhausted sequence receives 409 and fails; the last response is not repeated implicitly.

Response `kind` is one of `json` (`json` value), `text` (`text` string), or `malformed-json` (`text` must fail JSON parsing). Every response requires `status` 200–599 and optional `delayMs` 0–5000 (default 0). Each serialized response is bounded at 64 KiB. JSON/text content types are generated by the gateway; redirect headers and real-service fallback are unavailable.

| Assertion target | Selector fields | Expected value |
| --- | --- | --- |
| `execution.status` | none | `success`, `error`, `canceled`, `crashed` |
| `node.executed` | `nodeId` | boolean |
| `node.count` | `nodeId`, `runIndex`, `outputIndex` | integer item count |
| `node.json` | previous selectors plus `itemIndex`, `pointer` | JSON value |
| `requests.count` | `mockId` | integer request count |
| `request.json` | `mockId`, `requestIndex`, `pointer` | JSON value |
| `request.header` | `mockId`, `requestIndex`, lowercase `header` | string |

Indices default to zero and are bounded at 0–1000. Pointers are RFC 6901 (`~0`, `~1` escapes), maximum 512 characters; `""` selects the root. Missing is distinct from null. Missing expected requests/fields fail assertions; absent required saved node/output data raises explicit evidence errors. Actual error runs may have no output; use status and node.executed when expecting a workflow error. `node.executed: false` is meaningful only after correlated terminal execution evidence is available. Zero request counts are evaluated after completion and cleanup, not at startup.

Automatic assertions forbid unexpected requests. Quota, incomplete-capture or missing-execution errors cannot be overridden by test assertions. Sealed namespaces remain through the suite's final evidence cutoff, and authenticated in-flight bodies are drained with a two-second bound. Traffic after the suite ends/gateway closes is rejected; no indefinite observation window is claimed.

Reports use `schemaVersion: 1`, `runId`, `suite`, timestamps/duration, planned count, tests and exitCode. Tests distinguish `passed`, `failed`, `error`; include assertion results, actual normalized execution/request evidence, source/fixture hashes, transformations and cleanup state. JUnit uses failure for assertions, error for infrastructure and never marks unsupported cases skipped. Automatic secret-field and configured-literal redaction applies to console, JSON and JUnit; non-synthetic email addresses and identifying proxy IP headers are redacted. See SECURITY for limitations.
